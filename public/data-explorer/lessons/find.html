What this lesson is for

Until now you have looked at your whole table. But usually you want just a part of it — only your own district, only the big catches, or only a few columns.

This lesson gives you three simple commands to do that: list the values in a column, keep only the rows you want, and keep only the columns you want. At the end you will also learn what to do when something goes wrong — because it will, and it is easy to fix.

Press Run on each box. Remember: you cannot break anything.

// SHARED DATA BRIDGE for every Data Explorer lesson — include it with:
//     {{< include _landings-data.qmd >}}
// It fetches the signed-in user's capped, permission-filtered landing records from
// GET /api/data-download/explorer-data and publishes them as the OJS value `landings_data`.
// Each lesson then hands that value to a {webr} cell with quarto-live's `input` option, where the
// array of row objects becomes an R data.frame (types preserved, no CSV parsing).
// Keep this the ONLY copy: it encodes the contract with the app — the localStorage keys `authToken`
// and `apiBaseUrl` (published by getApiBaseUrl in src/utils/axiosConfig.ts) and the endpoint path.
// Reading the base URL from localStorage is what lets a static lesson reach the API exactly like the
// app does: dev -> http://localhost:3001/api, prod -> same-origin /api.
// NOTE: everything explanatory lives in these JS comments on purpose. A prose comment outside the
// code fence would be re-parsed as markdown at the first blank line and shown on the lesson page.
landings_data = {
  const token = localStorage.getItem("authToken");
  if (!token) return [];
  const apiBase = localStorage.getItem("apiBaseUrl") || "/api";
  const res = await fetch(`${apiBase}/data-download/explorer-data`, {
    headers: { Authorization: `Bearer ${token}`, Accept: "application/json" }
  });
  if (!res.ok) { console.warn(`explorer-data fetch failed: ${res.status}`); return []; }
  return await res.json();
}

Show only the rows you want

filter() keeps only the rows that match a condition you give — for example, only the gillnet trips.

Two small things to get right:

  • Use two equals signs == for “is equal to” (one = means something else and will not work).
  • A word like "gillnet" needs quotes. A number, like 5, does not.

First, have a guess. Look back at the little example table at the top of the page. It has 5 rows. Now think about what filter(example, gear == "gillnet") will give back.

Guessing first is not a test. It is the fastest way to understand what a command does, and a wrong guess teaches you more than a right one.

When the answer comes back red

Now that you are typing, sooner or later you will press Run and get red text instead of a table. This happens to everyone, every day, including the people who wrote these lessons.

Red text is not damage. Nothing is broken, nothing is lost, and your real data cannot be changed from this page. Red text is simply R saying: “I did not understand one word.”

You do not need to read all of it. Look for the last line — that is the useful one.

Almost every red message you will meet is one of just two. Here is each one, and what to do.

“object … not found”

This means R met a name it does not recognise. There are two common reasons.

The name is spelled differently from your data. The box below has a mistake on purpose. Press Run to see the red text, then fix the spelling and press Run again.

What you should see: a red line ending in object 'geer' not found. R is telling you the name it could not find — geer. Change it to gear and the table comes back.

When this happens on your own data, check the real spelling with names(landings), or with the distinct() list further up the page.

A word is missing its quotes. filter(example, gear == gillnet) gives the same message, object 'gillnet' not found. Without quotes, R thinks gillnet is the name of a column.

Words always need quotes, like "gillnet". Numbers never do, like 5.

“We detected a named input”

This one means you typed one = where two are needed. Press Run to see it, then fix it.

What you should see: red text saying R detected a named input, and suggesting you meant ==. It is right. Change the single = to == and press Run.

Two ways out, always
  • Edit and press Run again. You can do this as many times as you like.
  • Press “Start Over” on the box to put the original instruction back, exactly as it was when the page opened.

You cannot get stuck, and you cannot break anything.

Do two steps at once: the pipe |>

Most real questions need two steps: keep only your district, and keep only a few columns. The little symbol |> (called the pipe) lets you do steps in order, left to right. Read it as the word “then”.

What you have learned

  • distinct(table, column) — list the values in a column once (find your districts, gears, …).
  • filter(table, condition) — keep only the rows that match (use ==, and quotes for words).
  • select(table, columns…) — keep only the columns you name.
  • |> (“then”) — do several steps in order.

And when the answer comes back red:

  • object ... not found — a name is spelled wrong, or a word is missing its quotes.
  • named input — you typed one = where you need two, ==.
  • Either way: edit and press Run again, or press Start Over. Nothing is broken.
